# Troubleshooting

Every entry below is a failure that occurred in this repository, not a
hypothetical. They are grouped by what you see, because that is what you have
when you arrive.

## Build fails with "Incompatible environment configuration"

Working as intended. The build refuses combinations that would deploy something
broken:

| Message                                                    | Cause                                |
| ---------------------------------------------------------- | ------------------------------------ |
| `USE_MOCKS must be "true" when RUNTIME_MODE="demo"`        | A demo has no backend to talk to     |
| `USE_MOCKS must be "false" when RUNTIME_MODE="production"` | MSW is not in the bundle             |
| `AUTH_ADAPTER="mock" is not valid in production`           | Its endpoints exist only inside MSW  |
| `API_URL … points at the placeholder host`                 | `localhost`, `api.example.com`, etc. |

The last one surprises people. A build pointing at `api.example.com` deploys
successfully and then fails one request at a time — failing the build is the
kinder outcome.

## The demo shows stale data after a deploy

The service worker was cached. `mockServiceWorker.js` must be served with
`Cache-Control: no-cache`; a cached worker keeps serving the previous deploy's
handlers indefinitely and produces no error anywhere.

`vercel.json` and `public/_headers` both set this. If you host elsewhere, copy
it.

To recover in a browser: devtools → Application → Service Workers → Unregister,
then hard reload.

## Requests return HTML instead of JSON

The SPA fallback is rewriting `/api/*` to `index.html`. The rewrite must exclude
API paths:

```json
"source": "/((?!api/|assets/|mockServiceWorker\\.js|favicon\\.ico|robots\\.txt).*)"
```

Without the exclusion a missing API route returns a 200 with an HTML body, which
surfaces as a JSON parse error a long way from the cause.

## A page is blank and the console says nothing

Almost always a module-eval throw. `app.config.ts` used to throw on invalid env
in production, which turned one bad variable into a white screen.

Config validation is now lenient in the browser — it warns and falls back. If
you add module-scope code that can throw, don't.

## The table renders no rows but the footer counts them

Seen as _"Showing 0-0 of 48 rows"_ with an empty body.

The body and the footer are reading different sources. `useDataTable`'s
`manualPagination` watcher calls `table.setOptions(prev => ({ ...prev, … }))`,
and spreading the live options proxy **materialises the `data` getter**,
freezing whatever it held at that moment. The effect fires when `rowCount`
arrives — the same tick the rows arrive — so it is a race.

Fixed by re-declaring the getter after the spread. If you write a similar
`setOptions` call, preserve `data` explicitly.

## A list page crashes with "Cannot access 'X' before initialization"

You wired `useDataTable` to a query by hand. The two are mutually dependent, and
`useDataTable` evaluates its `rowCount` getter during setup — before a `const`
declared below it exists. It type-checks perfectly.

Use `useServerTable`, which owns the ordering.

## `vp fmt` fails with "Expected a fmt field in the default export"

`vite.config.ts` was converted to a callback (`defineConfig(({ mode }) => …)`).
Vite+ reads `lint`, `fmt` and `staged` off a **static** default export and
cannot call a function to find them.

Mode-dependent config belongs in a plugin's `config` hook, which is where
`vuestrata:env` lives.

## The formatter moves an import above the file's docblock

The docblock was attached to whichever import sorted first, and sorting moved
it. Order the imports so the one carrying the comment stays put, or move the
comment to the very top with a blank line after it.

## Production bundle still contains MSW

Check the module's `mockHandlers`. **Both** guards are required:

```ts
...(__VUESTRATA_DEMO__
  ? { mockHandlers: async () => (await import('./mocks/x.handlers')).xHandlers }
  : {}),
```

A dynamic `import()` alone is not enough. If the property is always constructed,
the arrow function survives, the bundler must assume it may be called, and the
msw chunk is emitted.

`node scripts/build/verify-bundle.mjs --mode=production` catches this.

## Auth works in dev and 401s in production

Transport mismatch. `bearer` sends `Authorization` with `credentials: 'omit'`;
`cookie` sends `credentials: 'include'` with a CSRF header and no
`Authorization`. Sending both is a CSRF hole, so the template sends exactly one.

Confirm `VUESTRATA_AUTH_ADAPTER` matches what your backend expects, and that
your CORS policy allows credentials if you use cookies.

## A route redirects to /403 for a user who should have access

Check three layers in order:

1. Does the role grant the permission?
   `resolveRolePermissions('manager')` in `inheritance.ts`.
2. Is the permission in the `BuiltinPermission` union? An unregistered string
   fails every check.
3. Does the route's `meta` name the permission you think it does?

A route with `requiredPermission` but no `requiresAuth` used to be open to
anonymous visitors — the checks were nested inside `if (isAuthenticated)`. They
now run for every visitor and fail closed.

## Sidebar entry highlighted on every page

Missing `exact: true`. `/dashboard` prefixes every path in the app.

## Sidebar entry missing entirely

In order of likelihood: the permission is not granted to the role; the module is
not in `src/modules/setup.ts`; the module is registered but not enabled; or a
parent's children were all filtered away and the parent had no `to` of its own.

## Translations show as raw keys

The module's `i18n` object is missing the locale, or the key is misspelled.
Collisions are reported at boot in development — if two modules define the same
key, the last one loaded wins and the warning names both.

## e2e tests fail in a full run and pass in isolation

A known cascade. One test hitting a long timeout (the MFA flow is the usual
culprit) starves the ones after it, producing a cluster of unrelated failures.

Confirm by running the failing spec alone before investigating it. Running with
`--project=chromium` and fewer workers also isolates it.

## `logInAsDemoAdmin` times out

The helper waits for a signed-in shell marker. When sign-out moved into the
account menu, the old marker — a visible "Sign out" button — stopped existing
until the menu was opened, and every test that logs in hung.

If you move the account controls, update `waitForSignedInShell` in
`e2e/helpers/auth.ts`.

## axe reports `button-name` on a select

A Reka select trigger is a `<button role="combobox">` whose content is the
selected value. A `placeholder` never becomes its accessible name. Add
`aria-label`.

## axe reports `definition-list` / `dlitem`

A `<dl>` may contain only `<dt>`/`<dd>` pairs or `<div>` groups, and a group may
contain only the pair. Putting a card component between the `<dl>` and its pairs
buries them — component wrappers add their own elements.

Either make the group `<div>` the styled element, or move the extra content
inside the `<dd>`.

## Docs reference a file that no longer exists

```bash
node scripts/docs/check-links.mjs
```

Runs in CI. It verifies that every `src/`, `scripts/`, `e2e/` and `test/` path
mentioned in the docs exists, and that relative links resolve. It cannot check
prose — but it removes the excuse that a stale path went unnoticed.

Paths containing `your-` are treated as files the reader is told to create.
