# Creating a Module

A domain module owns one noun end to end: its contract, its mock backend, its
queries, its pages, its translations and its navigation entries. The eight
shipped domains (`customers`, `orders`, `catalog`, `projects`, `calendar`,
`messages`, `team`, `reports`) are all built this way — read any of them
alongside this page.

Prefer `vp run gen:module <name>` — it writes these files and registers the
module in `setup.ts`. This page is the long form of what the generator emits
and what it leaves to you. See [Add a module](/docs/recipes/add-a-module).

This walkthrough uses `invoices`.

## 1. Folder

```bash
mkdir -p src/modules/invoices/{composables,mocks,pages,i18n}
```

## 2. The contract comes first

The zod schema is the agreement between your mock backend, your queries and
eventually your real API. Write it before anything else.

```ts
// src/modules/invoices/types.ts
import { z } from 'zod'

import type { CollectionFilters } from '~/lib/api/collection-queries'
import { moneySchema } from '~/lib/money'

export const INVOICE_STATUSES = ['draft', 'sent', 'paid', 'overdue'] as const
export type InvoiceStatus = (typeof INVOICE_STATUSES)[number]

export const invoiceSchema = z.object({
  id: z.string(),
  number: z.string(),
  customerName: z.string(),
  status: z.enum(INVOICE_STATUSES),
  total: moneySchema,
  issuedAt: z.string(),
  dueAt: z.string(),
})

export type Invoice = z.infer<typeof invoiceSchema>

export interface InvoiceFilters extends CollectionFilters {
  status?: InvoiceStatus | 'all'
}
```

Two rules worth taking seriously:

- **Money is `moneySchema`** — a minor-unit integer plus an ISO-4217 code, never
  a formatted string and never a float. `"$45,231"` cannot be summed, compared
  or localized; `0.1 + 0.2` is not `0.3`.
- **Derive, do not store, anything computable.** A stored `isOverdue` flag is
  correct until midnight.

## 4. Server state

If the resource is a standard REST collection, you write almost nothing:

```ts
// src/modules/invoices/composables/useInvoices.ts
import { createCollectionApi } from '~/lib/api/collection-queries'

import { invoicesModuleKeys } from '../query-keys'
import { invoiceSchema, type Invoice, type InvoiceFilters } from '../types'

const invoicesApi = createCollectionApi<Invoice, InvoiceFilters>({
  resource: 'invoices',
  schema: invoiceSchema,
  keys: invoicesModuleKeys,
})

export const useInvoicesQuery = invoicesApi.useList
export const useInvoiceQuery = invoicesApi.useDetail
export const useCreateInvoiceMutation = invoicesApi.useCreate
export const useUpdateInvoiceMutation = invoicesApi.useUpdate
```

You get pagination, search, sorting, filtering, cache invalidation and — the
important one — **response validation**. A backend that drifts from the schema
fails at the boundary instead of rendering `undefined` three components deep.

For anything that is not a collection (an aggregate, an action, a report), write
a plain TanStack Query composable.

## 5. Mock backend

Demo builds only.

```ts
// src/modules/invoices/mocks/invoices.handlers.ts
import { createCollectionMock } from '~/mocks/collection'

import type { Invoice } from '../types'
import { invoiceFixtures } from './fixtures'

const invoicesMock = createCollectionMock<Invoice>({
  resource: 'invoices',
  seed: invoiceFixtures,
  searchFields: ['number', 'customerName'],
  filterFields: ['status'],
  defaultSort: { by: 'issuedAt', order: 'desc' },
})

export const invoicesHandlers = invoicesMock.handlers
export const resetInvoicesMock = invoicesMock.reset
```

Fixtures must be **deterministic** — use the seeded helpers in
`src/modules/app/mocks/seed.ts`, never `Math.random()`. Random data means a
screenshot cannot be reproduced and an e2e test cannot assert on a row.

Make the data internally consistent, too. A "starter" account billing more than
an "enterprise" one teaches the reader that none of the numbers mean anything,
and they stop reading the UI.

## 6. Pages

A page is an inbound adapter: it normalizes route input, handles route-level
concerns and composes the feature. Reusable logic belongs in the module, not in
the page — see [Route Pages](../2.architecture/4.route-pages.md).

Reuse the patterns rather than inventing new ones:

| You need              | Look at                                                            |
| --------------------- | ------------------------------------------------------------------ |
| Server-backed table   | `src/modules/customers/pages/index.vue`                            |
| Record page           | `src/modules/customers/pages/detail.vue`                           |
| Create/edit form      | `src/modules/customers/pages/form.vue`                             |
| Multi-step form       | `src/modules/orders/components/OrderDraftForm.vue`                 |
| Card grid             | `src/modules/catalog/pages/index.vue`                              |
| Kanban                | `src/modules/projects/components/ProjectBoardScreen.vue`           |
| Calendar              | `src/modules/calendar/pages/index.vue`                             |
| Master/detail         | `src/modules/messages/pages/index.vue`                             |
| Permission-restricted | `src/modules/reports/pages/index.vue`                              |
| Page → screen split   | `src/modules/users/pages/users.vue` + `components/UsersScreen.vue` |

The last three rows are the two shapes a route can take. Most routes are a
single cohesive surface and stay one file; a feature with its own workflow —
a board, a multi-step form, a filtered timeline — earns a screen the page
composes.

For a list page use `useServerTable` with `createColumns` — do **not** wire
`useDataTable` to a query yourself. The two are mutually dependent (the table
needs a row count, the count comes from the query, the query needs the table's
filters), and writing that by hand produces a temporal dead zone that
type-checks perfectly and crashes on load. Pass the columns `computed`, not
`columns.value`, so a locale change can rebuild headers.

```ts
const { table, isLoading, isError, refetch } = useServerTable<Invoice, InvoiceFilters>({
  columns,
  query: useInvoicesQuery,
  extra: () => ({ status: status.value }),
})
```

Every page must handle **error, loading and empty as three distinct states**. An
error is not an empty list: showing "no invoices match" for a failed request
tells the user their filters are wrong when the data is simply unknown. Pass
`:error` and `@retry` on `UiDataGrid` rather than swapping the grid for a
separate empty state.

## 7. Module entry

```ts
// src/modules/invoices/index.ts
import type { ModuleDefinition } from '../types'
import invoicesI18nAr from './i18n/ar.json'
import invoicesI18nEn from './i18n/en.json'
import invoicesI18nFr from './i18n/fr.json'

const invoicesModule: ModuleDefinition = {
  config: {
    id: 'invoices',
    name: 'Invoices',
    description: 'Invoicing and payment status',
    version: '1.0.0',
    category: 'commerce',
    order: 40,
    enabledByDefault: true,
    permissions: ['invoices:read', 'invoices:manage'],
  },

  routes: [
    {
      path: '/dashboard/invoices',
      name: '/dashboard/invoices',
      component: () => import('./pages/index.vue'),
      meta: {
        layout: 'dashboard',
        requiresAuth: true,
        requiredPermission: 'invoices:read',
        module: 'invoices',
        title: 'invoices_nav',
      },
    },
  ],

  navItems: [
    {
      label: 'invoices_nav',
      icon: 'card',
      to: '/dashboard/invoices',
      permission: 'invoices:read',
      group: 'commerce',
      order: 40,
    },
  ],

  ...(__VUESTRATA_DEMO__
    ? { mockHandlers: async () => (await import('./mocks/invoices.handlers')).invoicesHandlers }
    : {}),

  i18n: { en: invoicesI18nEn, fr: invoicesI18nFr, ar: invoicesI18nAr },
}

export default invoicesModule

export { useInvoicesQuery, useInvoiceQuery } from './composables/useInvoices'
export { invoicesModuleKeys } from './query-keys'
export type { Invoice, InvoiceFilters, InvoiceStatus } from './types'
```

::alert{type="warning"}
**The `mockHandlers` spread is not optional.** Two guards are required and they
do different jobs: the dynamic `import()` keeps `msw` out of the barrel's static
module graph, and the `__VUESTRATA_DEMO__` ternary lets rolldown drop the import
entirely. Declaring `mockHandlers` unconditionally — even with a dynamic import
inside — keeps the arrow function alive, so the bundler must assume it may be
called and emits the msw chunk into a production build that can never call it.
::

## 8. Route ordering

Declare static segments **before** dynamic ones:

```ts
{ path: '/dashboard/invoices/new' },   // first
{ path: '/dashboard/invoices/:id' },   // second
```

vue-router matches equally-ranked paths in registration order. Reversed, the
create page tries to load an invoice with the id `"new"`.

## 9. Permissions

Permissions are a closed union. Add yours to
`src/modules/core/lib/rbac/types.ts` and grant them in
`src/modules/core/lib/rbac/inheritance.ts`:

```ts
manager: { delta: ['invoices:manage' /* … */] },
viewer:  { delta: ['invoices:read'   /* … */] },
```

A closed union means `can('invoice:read')` — note the missing plural — is a
compile error rather than a check that always returns false and silently hides a
page.

Nothing else needs updating: the demo account, the RBAC registry and the e2e
helper all derive their permission lists from the hierarchy.

## 10. Navigation

`group` refers to `src/modules/nav-groups.ts`. Modules cannot define groups — if
they could, two modules contributing to one section would each carry a copy of
the heading and could disagree about its order.

Use `exact: true` for an index entry whose path prefixes its own siblings, and
`children` for a nested section (see `orders` and `messages`).

## 11. Translations

One JSON file per locale, keys prefixed with the module id. Collisions are
reported at boot in development — merging is last-write-wins, and with enough
modules reaching for `common_status` it is a matter of when, not if.

## 12. Register it

```ts
// src/modules/setup.ts
import invoicesModule from './invoices'

export const appModules: ModuleDefinition[] = [
  // …
  invoicesModule,
]
```

## Checklist

- [ ] zod schema written first; money uses `moneySchema`
- [ ] Fixtures deterministic and internally consistent
- [ ] `mockHandlers` behind the `__VUESTRATA_DEMO__` spread
- [ ] Static routes declared before dynamic ones
- [ ] Permissions added to the union and granted to roles
- [ ] `group` set on every nav item; `exact` where a path prefixes siblings
- [ ] Every sidebar link points at a page that exists
- [ ] Error, loading and empty handled as distinct states
- [ ] Translations for en, fr and ar
- [ ] Registered in `src/modules/setup.ts`
- [ ] `node scripts/build/verify-bundle.mjs --mode=production` still passes
