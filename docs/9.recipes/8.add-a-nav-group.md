# Add a Nav Group

A nav group is a sidebar section heading: **Overview**, **Commerce**, **Work**,
**Organization**, **Account**, **Reference**.

## Modules cannot define groups, on purpose

`ModuleNavItem.group` references a group **by id**. The heading text and its
position live once, in `src/modules/nav-groups.ts`.

If modules could define groups, two modules contributing to the same section
would each carry their own copy of the label and could disagree about its order
— and the sidebar would sprout a new heading every time someone typed a slightly
different string.

The cost of that choice: an unknown group id does not error. `resolveNavGroup`
falls back to `overview`, because silently _hiding_ a navigation entry is a far
worse failure than showing it under the wrong heading. So a typo is invisible at
runtime — which is why `module-contract.test.ts` asserts every `group` resolves
to a real entry.

## Adding one

**1. Register it:**

```ts
// src/modules/nav-groups.ts
export const NAV_GROUPS: readonly ModuleNavGroupDefinition[] = [
  { id: 'overview', label: 'nav_group_overview', order: 10 },
  // …
  { id: 'insights', label: 'nav_group_insights', order: 35 },
]
```

`label` is an **i18n key**, not display text — groups render through `t()`.
`order` must be unique; `registry-drift.test.ts` fails on duplicates, because
equal orders make sidebar position depend on registration order rather than
intent. Leave gaps of 10 so a section can be inserted later without renumbering.

**2. Translate the label** in all three shell catalogs —
`src/modules/app/locales/{en,fr,ar}.json`:

```json
"nav_group_insights": "Insights"
```

Both `registry-drift.test.ts` and `i18n-parity` fail if you miss one.

**3. Point modules at it:**

```ts
navItems: [
  { label: 'reports_nav', icon: 'chart', to: '/dashboard/reports', group: 'insights', order: 10 },
]
```

## Empty groups disappear

A group with no visible items is dropped from the sidebar entirely. Permission
filtering can legitimately empty a whole section for some roles, and a heading
with nothing under it is a promise the UI cannot keep.

So a new group shows up only once a module contributes an item the current user
may see. If your group is not appearing, check the permission on its nav items
before suspecting the registration.

## Verify

```bash
vp check && vp test --run
vp dev    # the section appears once a module points at it
```
