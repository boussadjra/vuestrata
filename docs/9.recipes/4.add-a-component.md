# Add a Component

```bash
vp run gen:component Tag             # presentational wrapper
vp run gen:component Rating --field  # wrapper + forms composable
```

The `Ui` prefix is added for you: `gen:component Tag` produces `UiTag.vue`.

## The split

- **`components/ui/Ui<Name>.vue`** — markup, variants, and the `data-ui` /
  `data-variant` attributes the theme layer styles against. Nothing stateful.
- **`composables/forms/useUi<Name>.ts`** — labels, hints, errors, keyboard
  handling, validation binding. Only for fields; `--field` writes it.

There is no `components/ui/base/` folder. Shared behaviour lives in the `forms/`
composables, not in intermediate `Base*.vue` components — a `Ui*` wrapper is the
only component in the chain. That split is what keeps 69 wrappers from
duplicating label/hint/error handling, and it keeps the logic unit-testable
without mounting anything.

Both barrels are updated for you.

## Colour: semantic tokens only

The generated template uses semantic tokens exclusively (`bg-card`,
`text-muted-foreground`, `border-border`, `text-destructive`). This is not
style preference — the `no-raw-palette` lint rule **rejects** `bg-blue-500` and
friends, because a raw palette utility renders identically under all ten themes
and needs a hand-written `dark:` twin that is easy to get wrong.

See [Semantic tokens](/docs/theming/semantic-tokens) for the full vocabulary.

## Still yours to do

1. **The props interface.** The generated `variant` / `size` unions are a
   starting shape.
2. **The `data-ui` value.** The generator derives it from the name. If your
   component is a variation of something that already exists, reuse that
   component's value so themes style both — a new value means every theme that
   cares has to learn about it.
3. **Accessibility.** The field template wires `aria-describedby` and
   `aria-invalid`; anything beyond a plain input (listbox, combobox, dialog)
   should be built on the matching Reka primitive rather than hand-rolled roles.
4. **A test** at `test/component/ui/<name>.test.ts`.
5. **Docs**, optionally: an entry in `COMPONENT_DEMO_DOCS`
   (`src/modules/app/config/component-docs.ts`) plus a demo page under
   `src/modules/app/pages/components/`.

## The provider prop

Most wrappers take `provider?: 'reka'` and render it as `data-provider`. It
exists so a second headless library could be introduced behind the same public
API without touching call sites. Today `'reka'` is the only implementation —
keep the prop for consistency.

## Verify

```bash
vp check && vp test --run
vp dev    # /components shows the showcase pages
```
