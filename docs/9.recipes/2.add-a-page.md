# Add a Page

```bash
vp run gen:page payments settlements --kind list
```

## The thing that surprises people

**Module pages are not file-routed.** `vite.config.ts` scans only
`src/modules/app/pages` and `src/modules/auth/pages`. A `.vue` file dropped into
`src/modules/payments/pages/` gets you nothing — no route, no URL, no error.

Domain pages reach the router through their module's `routes` array, registered
at runtime by `setupModules()`. That indirection is not ceremony: it is what
applies the layout wrapper and the RBAC meta, and what lets a disabled module
contribute no routes at all.

So this generator's real work is editing `src/modules/<module>/index.ts`. The
`.vue` file is the easy half.

> A `{ src: 'src/modules/*/pages' }` entry used to sit in the router config and
> did nothing — the plugin never expands that glob. It has been removed. If you
> are looking for a module page in `typed-router.d.ts`, that is why it was never
> there.

## Options

| Flag                               | Purpose                                                                       |
| ---------------------------------- | ----------------------------------------------------------------------------- |
| `--kind list\|detail\|form\|blank` | Which starting template. `detail` adds an `:id` segment. Defaults to `blank`. |
| `--nav`                            | Also add a sidebar entry for it.                                              |
| `--icon <name>`                    | Nav icon, with `--nav`.                                                       |

## What it writes

- `src/modules/<module>/pages/<name>.vue`
- a route in the module's `routes` array
- the title key in all three locale files
- a nav item, with `--nav`

## Route ordering is handled for you

vue-router matches equally-ranked paths in **registration order**, so a static
path declared after a dynamic sibling is unreachable — `/payments/new` declared
after `/payments/:id` means the create page tries to load a record with the id
`"new"`. The generator inserts static routes ahead of the first dynamic sibling,
and `module-contract.test.ts` fails if that ordering is ever broken by hand.

## What is still yours

The new route inherits the module's `<module>:read` permission. If the page
needs something stricter — an export page that should require `:manage` — change
`requiredPermission` on the route the generator added.

The page bodies are skeletons. `--kind list` renders an empty state; wire it to
the module's list query. Keep it thin: a route page coordinates, it does not
implement. The `no-restricted-imports` rule enforces that by rejecting
`@tanstack/vue-query` imports inside `pages/`.
