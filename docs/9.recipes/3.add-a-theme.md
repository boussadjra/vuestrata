# Add a Theme

```bash
vpr gen:theme midnight
vpr gen:theme midnight --label 'Midnight Blue'   # custom display label
```

## Four files must agree

| File                             | What breaks if you forget it                                                 |
| -------------------------------- | ---------------------------------------------------------------------------- |
| `styles/themes/<name>.css`       | Nothing to apply.                                                            |
| `styles/app.css` — the `@import` | The class resolves to nothing; the app silently renders the default palette. |
| `config/theme.config.ts`         | The theme never appears in the settings picker, so nobody can select it.     |
| `types/index.ts` — `ThemeName`   | No autocomplete, no type safety at call sites.                               |

The generator writes all four. `theme-registry` lint then keeps them in
agreement — it fails if any one drifts.

### The import-order trap

The `@import` must come **before** `semantic.css`. That file aliases every
semantic token (`--color-card`, `--color-border`, …) onto whichever ramp the
active theme installed; if the theme loads after it, the aliases resolve against
ramps that do not exist yet.

The result is a theme that is _almost_ right — accents correct, surfaces wrong —
which reads as a design mistake rather than a build-order one. That is why the
lint rule checks position, not just presence, and why the generator inserts
inside a sentinel region above `semantic.css`.

## Ramps

Define **four** ramps in both colour modes: `primary`, `secondary`, `accent`,
`surface`, each with steps 50–950. Every semantic token follows automatically.

`danger` is the fifth ramp the semantic layer reads, but it is declared once for
all themes in `app.css` — a destructive action should read as destructive
whichever theme is active. Override it in your theme only if that theme's
character genuinely demands a different warning hue.

The generated ramps are a neutral grey placeholder: immediately _valid_, and
obviously _unfinished_. Replace them.

## Still yours to do

1. **Replace the ramps.** All eleven steps of all four, in both modes.
2. **Fonts.** If the theme names a `--font-sans` that is not already loaded, add
   it to the Google Fonts link in `index.html`. A font that was never fetched
   falls back silently — this has happened before, which is why it is called out.
3. **Contrast.** Add `{ theme: 'midnight', dark: false }` to the axe matrix in
   `e2e/accessibility.spec.ts`.
4. **Component chrome**, optionally. Themes may style `[data-ui='card']`,
   `[data-ui='button']` and friends for genuine character — see
   `styles/themes/harbour.css` for a worked example with glass cards.

## Verify

```bash
vp check                      # includes the theme-registry rule
vpr dev                        # switch to it in Settings → Appearance
vpr test:e2e -- e2e/accessibility.spec.ts
```

Check both colour modes. A theme that only works in light mode is half a theme.
