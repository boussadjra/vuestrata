# Add an Icon Set

```bash
vpr gen:icon-set tabler
vpr gen:icon-set my-icons --prefix ph   # when the Iconify prefix differs
```

## How icons work here

Not `unplugin-icons`. The stack is `@egoist/tailwindcss-icons` over Iconify JSON
packs, so an icon is a **CSS class** — `i-solar-bolt-bold`.

Between the app and those classes sits a semantic layer:

- `IconName` (`src/modules/app/types/index.ts`) is a closed union of ~65
  meaning-based names: `users`, `danger-triangle`, `chevron-down`.
- Each provider map is `Record<IconName, string>`, mapping every semantic name
  to that pack's class.
- `AppIcon` renders `<AppIcon name="users" />` through the active provider.

Call sites name _meaning_, never a pack-specific class. That is what makes
swapping providers a config change instead of a find-and-replace.

## What the generator does

It reads `IconName` from the union itself and emits a **complete, pre-filled**
map — all ~65 keys present and typed. Values are guessed as
`i-<prefix>-<semantic-name>`, and many will be wrong.

That is the intended trade. Typing the list by hand is exactly how the old
`ICON_NAMES` array in `custom.ts` fell nine names behind the union without
anyone noticing — every consumer of `createCustomIconMap` silently got nine
unfillable slots. Keys complete and values wrong is a state the compiler and the
`icon-parity` lint rule can both see; keys missing is not.

## Still yours to do

1. **Correct the values** against the real pack. Iconify names rarely match our
   semantic names.
2. **Install the pack** if it is not a dependency: `vp add -D @iconify-json/tabler`.
3. **Register the collection** in `src/modules/app/styles/icons-plugin.mjs`. That
   list is what Tailwind turns into `i-<prefix>-*` CSS; a pack missing from it
   generates no rules and every icon in the map renders blank.
4. **Register it as selectable**: add the name to `ICON_PROVIDERS` in
   `src/modules/core/lib/config/env.schema.ts` and to `builtinMaps` in
   `src/modules/app/config/icon-provider.ts`. Until then the map exists but
   cannot be chosen.

An entry left as an empty string renders an empty span with no error — which is
why `icon-parity` fails on one.

## Runtime registration

For a set that ships with a consumer's app rather than the template, skip the
generator and register at runtime:

```ts
import { createCustomIconMap, registerIconMap } from '@/icons'

registerIconMap('my-icons', createCustomIconMap({ users: 'i-my-users' /* … */ }))
```

`createCustomIconMap` fills every unspecified name with an empty string, so the
map is always complete — and `safeResolveIcon` falls back to `widget` for
anything unresolvable.

## Adding a new icon _name_

Different task. Add it to the `IconName` union, then to **all three** provider
maps — TypeScript enforces that, and `icon-parity` catches the untyped cases.

## Verify

```bash
node scripts/lint/run-custom-rules.mjs    # icon-parity
vp check
vpr dev    # Settings → Appearance → icon provider, then look at the sidebar
```
