# Adapter Systems

Vuestrata uses the **adapter pattern** extensively to provide plug-and-play flexibility across UI libraries, icon sets, validation engines, and auth strategies.

## UI Provider Adapter

The UI adapter lets you swap the underlying component library without changing page code.

```
<UiButton>  →  resolveUiComponent('Button')
                 ├── reka/RekaButton.vue       (Reka UI - headless)
                 └── vuetify0/V0Button.vue     (Vuetify stub)
```

### Available Providers

| Provider   | Library                | Status   |
| ---------- | ---------------------- | -------- |
| `reka`     | Reka UI 2.x (headless) | Full     |
| `vuetify0` | Vuetify (stub)         | Scaffold |

### Usage

All 55+ adapter components work identically regardless of provider:

```vue
<template>
  <UiButton variant="primary" size="lg">Click me</UiButton>
  <UiDialog v-model:open="dialogOpen">
    <template #title>Confirm</template>
    <p>Are you sure?</p>
  </UiDialog>
</template>
```

### Base Component Layer

Complex components that embed library logic (e.g., Formwerk for forms) use an additional **Base** layer to keep providers decoupled:

```
UiForm  →  resolveUiComponent('Form')
              ├── reka/RekaForm.vue       (styling only)
              └── vuetify0/V0Form.vue     (styling only)
                    ↓
              base/BaseForm.vue           (unstyled, Formwerk logic)
```

Base components live in `src/modules/app/components/ui/base/` and contain all framework integration logic. Provider components in `src/modules/app/components/ui/provider/<name>/` wrap a Base and add only styling — they never import from each other.

## Icon Adapter

Icons use semantic names mapped to CSS classes per icon set:

```vue
<AppIcon name="bolt" size="lg" />
```

### Icon Sets

| Provider   | Library        | Icons        |
| ---------- | -------------- | ------------ |
| `solar`    | Solar Icons    | 55+ mappings |
| `lucide`   | Lucide Icons   | 55+ mappings |
| `phosphor` | Phosphor Icons | 55+ mappings |

### Custom Icon Maps

```ts
import { registerIconMap, createCustomIconMap } from '~/config/icon-provider'

const myIcons = createCustomIconMap({
  bolt: 'my-icon-lightning',
  user: 'my-icon-person',
  // ... extend from an existing map
})

registerIconMap('custom', myIcons)
```

## Validation Adapter

Validation adapters are lazy-loaded to minimize bundle size:

```ts
const { validate, validateField } = await createValidator('zod')
```

### Available Adapters

| Adapter   | Library | Features                       |
| --------- | ------- | ------------------------------ |
| `zod`     | Zod     | Default, full schema inference |
| `valibot` | Valibot | Ultra-lightweight alternative  |
| `yup`     | Yup     | Established, chain-based API   |
| `arktype` | ArkType | TypeScript-native validation   |

Each adapter implements the `ValidationAdapter` interface:

```ts
interface ValidationAdapter {
  validate(schema: unknown, data: Record<string, unknown>): Promise<ValidationResult>
  validateField(schema: unknown, field: string, value: unknown): Promise<string | null>
}
```

## Auth Adapter

Auth supports multiple strategies via the adapter pattern:

```ts
const {
  login,
  register,
  socialLogin,
  logout,
  fetchUser,
  sendMagicLink,
  verifyMagicLink,
  setupMfa,
  verifyMfaCode,
  disableMfa,
} = useAuth()
```

### Strategies

| Adapter | Env Value                      | Flow                        |
| ------- | ------------------------------ | --------------------------- |
| Mock    | `VUESTRATA_AUTH_ADAPTER=mock`  | MSW-backed development auth |
| JWT     | `VUESTRATA_AUTH_ADAPTER=jwt`   | JSON Web Token auth         |
| OAuth   | `VUESTRATA_AUTH_ADAPTER=oauth` | OAuth 2.0 / social login    |
