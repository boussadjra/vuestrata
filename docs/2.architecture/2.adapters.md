# Adapter Systems

Vuestrata keeps one fixed UI component implementation and uses the **adapter pattern** where runtime flexibility still adds value: icons, validation engines, and auth strategies.

## UI Wrapper Layer

The public `Ui*` components remain the stable import surface for the app, but they now target the repo's Reka UI implementation directly.

```
<UiButton>  →  UiButton.vue
```

### Usage

The wrapper surface stays consistent for app code:

```vue
<template>
  <UiButton variant="primary" size="lg">Click me</UiButton>
  <UiDialog v-model:open="dialogOpen">
    <template #title>Confirm</template>
    <p>Are you sure?</p>
  </UiDialog>
</template>
```

### Shared Field Behaviour

Components that embed shared logic (Formwerk wiring for form fields) delegate it to a composable rather than an intermediate component:

```
UiTextField  →  UiTextField.vue                    (public wrapper: template + styling)
    ↓
         composables/forms/useUiTextField.ts   (Formwerk bindings, labels, errors)
```

There is no `components/ui/base/` folder. Shared behaviour lives in `src/modules/app/composables/forms/`, and a `Ui*` wrapper is the only component in the chain. See [Ui Wrapper Architecture](/docs/components/provider-architecture).

## Icon Adapter

Icons use semantic names mapped to CSS classes per icon set:

```vue
<AppIcon name="bolt" size="lg" />
```

### Icon Sets

| Provider   | Library        | Mapping Style       |
| ---------- | -------------- | ------------------- |
| `solar`    | Solar Icons    | Shared semantic map |
| `lucide`   | Lucide Icons   | Shared semantic map |
| `phosphor` | Phosphor Icons | Shared semantic map |

### Custom Icon Maps

```ts
import { registerIconMap, createCustomIconMap } from '~/config/icon-provider'

const myIcons = createCustomIconMap({
  bolt: 'my-icon-lightning',
  user: 'my-icon-person',
  // ... extend from an existing map
})

registerIconMap('custom', myIcons)
```

## Validation Utilities

Validation standardizes on Zod:

```ts
const { validate, validateField } = await createValidator('zod')
```

The shared `ValidationAdapter` interface remains so framework-agnostic code can validate through one contract:

```ts
interface ValidationAdapter {
  validate(schema: unknown, data: Record<string, unknown>): Promise<ValidationResult>
  validateField(schema: unknown, field: string, value: unknown): Promise<string | null>
}
```

## Auth Adapter

Auth supports multiple strategies via the adapter pattern:

```ts
const {
  login,
  register,
  socialLogin,
  logout,
  fetchUser,
  sendMagicLink,
  verifyMagicLink,
  setupMfa,
  verifyMfaCode,
  disableMfa,
} = useAuth()
```

### Strategies

| Adapter | Env Value                      | Flow                        |
| ------- | ------------------------------ | --------------------------- |
| Mock    | `VUESTRATA_AUTH_ADAPTER=mock`  | MSW-backed development auth |
| JWT     | `VUESTRATA_AUTH_ADAPTER=jwt`   | JSON Web Token auth         |
| OAuth   | `VUESTRATA_AUTH_ADAPTER=oauth` | OAuth 2.0 / social login    |
