# Installation

## Prerequisites

- [Node.js](https://nodejs.org/) 22.22.2 or later on the 22 line, 24.15 or later on the 24 line, or
  26 and up. CI and the Docker image build on Node 22.
- [Vite+](https://viteplus.dev/guide/) (the `vp` CLI), at the version the project pins.

The toolchain itself (`vite-plus`) runs on Node `^20.19.0 || ^22.18.0 || >=24.11.0`. The floor above
is higher because the test environment, jsdom 30, needs `^22.22.2 || ^24.15.0 || >=26.0.0`: on an
older Node the app builds and `vpr test` does not start. `package.json` declares the same range under
`engines`.

Install the `vp` CLI before running the commands below, at the version the Dockerfile, `vercel.json`
and CI all pin (`vpr lint` fails when those disagree):

```bash
npm i -g vite-plus@0.2.9
```

## Quick Start

::code-group

```bash [vp]
# Your own copy: press "Use this template" on
# https://github.com/boussadjra/vuestrata, then clone the repository it creates
git clone https://github.com/<you>/<your-app>.git my-app
cd my-app

# Install dependencies
vp install

# Start dev server
vpr dev
```

```bash [Docker]
# Build and run with Docker Compose
docker compose up --build
```

::

The dev server runs at [http://localhost:3333](http://localhost:3333) by default.

That gets the template running. To turn it into _your_ app — install the CLI,
remove the demo modules, and set yourself up to keep taking updates — continue to
[Starting a Project](/docs/getting-started/starting-a-project).

## Project Structure

```
src/
├── modules/
│   ├── app/             # Main application module
│   │   ├── assets/      # Static assets (fonts, images)
│   │   ├── components/  # UI components + layout shell
│   │   │   ├── layout/  # AppHeader, AppSidebar, AppFooter
│   │   │   └── ui/      # Reka-backed Ui wrappers + shared base components
│   │   ├── composables/ # Composition functions (auth, RBAC, forms, tables)
│   │   ├── config/      # Runtime config, icons, themes, docs helpers
│   │   ├── layouts/     # Page layouts (default, auth, dashboard, blank)
│   │   ├── mocks/       # MSW browser worker + shared mock helpers
│   │   ├── pages/       # Vue Router file-based routes
│   │   ├── plugins/     # Vue plugins (router, pinia, i18n, vue-query)
│   │   ├── stores/      # Pinia stores — client-only state (auth, app, notification)
│   │   ├── styles/      # Tailwind CSS v4 + 12 theme presets + dark mode
│   │   └── types/       # Shared TypeScript types
│   ├── analytics/       # Dashboard, audit log, and charts module
│   ├── auth/            # Public auth pages, useAuth, and adapter orchestration
│   ├── billing/         # Billing module (server state via TanStack Query)
│   ├── core/            # Core module — shared utilities
│   │   └── lib/         # Framework-agnostic utilities (api, errors, logger, rbac, etc.)
│   ├── showcase/        # Forms and data-table demo module
│   ├── settings/        # Settings module (client state via Pinia)
│   └── users/           # Users module (server state via TanStack Query)
```

## Available Scripts

| Command                     | Description                        |
| --------------------------- | ---------------------------------- |
| `vpr dev`                   | Start Vite dev server on port 3333 |
| `vpr build`                 | Production build                   |
| `vpr preview`               | Preview production build           |
| `vp check`                  | Run format, lint, and typecheck    |
| `vpr lint`                  | Lint with oxlint                   |
| `vpr lint --fix`            | Lint and auto-fix                  |
| `vpr fmt`                   | Format with oxfmt                  |
| `vpr fmt --check`           | Check formatting without writing   |
| `vpr test`                  | Run Vitest in watch mode           |
| `vpr test --run`            | Run Vitest once                    |
| `vpr test:e2e`              | Run Playwright e2e tests           |
| `vpr test:e2e:ui`           | Run Playwright with interactive UI |
| `vpr test --run --coverage` | Run tests once with v8 coverage    |
| `vp outdated`               | Check for outdated packages        |
| `vp update`                 | Update dependencies                |
