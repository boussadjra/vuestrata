# Form Builder

## Quick start

```ts
import { z } from 'zod'
import { useFormBuilder } from '~/composables/useFormBuilder'

const schema = z.object({
  firstName: z.string().min(1, 'First name is required'),
  email: z.string().email('Invalid email'),
  role: z.enum(['admin', 'member', 'viewer']),
  newsletter: z.boolean(),
})

const {
  fields,
  values,
  isSubmitting,
  isDirty,
  isTouched,
  isValid,
  wasSubmitted,
  handleSubmit,
  setFieldValue,
  reset,
} = useFormBuilder({
  schema,
  fields: [
    { name: 'firstName', type: 'text', label: 'First name', required: true, colSpan: 1 },
    { name: 'email', type: 'email', label: 'Email', required: true, colSpan: 1 },
    {
      name: 'role',
      type: 'select',
      label: 'Role',
      colSpan: 1,
      options: [
        { label: 'Admin', value: 'admin' },
        { label: 'Member', value: 'member' },
        { label: 'Viewer', value: 'viewer' },
      ],
    },
    { name: 'newsletter', type: 'checkbox', label: 'Subscribe to updates', colSpan: 1 },
  ],
  initialValues: {
    role: 'member',
    newsletter: true,
  },
  onSubmit: async (payload) => {
    await api.users.create(payload)
  },
})
```

```html
<UiFormBuilder :fields="fields" :submitting="isSubmitting" :cols="2" @submit="handleSubmit" />
```

## Detailed form management usage

### 1. Define field metadata

Each field definition controls rendering, layout, and baseline UX:

- `name`: form path, supports dot notation
- `type`: determines which Ui component renders
- `label`, `placeholder`, `hint`: content and guidance
- `required`, `disabled`, `readonly`: behavior flags
- `colSpan`: responsive grid width in UiFormBuilder

### 2. Add schema validation

Pass any Standard Schema compatible object via `schema`.

```ts
const schema = z.object({
  profile: z.object({
    firstName: z.string().min(1),
    lastName: z.string().min(1),
  }),
  contact: z.object({
    email: z.string().email(),
  }),
})
```

Validation runs inside Formwerk during submit and field interaction.

### 3. Bind submit directly

`handleSubmit` from `useFormBuilder()` is already an event handler:

```html
<UiFormBuilder :fields="fields" @submit="handleSubmit" />
```

Do not wrap it in another function unless you need custom pre-submit side effects.

### 4. Read live form state

```ts
const canSubmit = computed(() => !isSubmitting.value && isValid())
const showValidationSummary = computed(() => isTouched() && !isValid())
const hasUserEdits = computed(() => isDirty())
```

### 5. Programmatically update fields

```ts
setFieldValue('role', 'viewer')
setFieldValue('newsletter', false)
```

Use this for API prefills, template presets, or wizard transitions.

### 6. Reset behavior

```ts
await reset() // back to initialValues

await reset({
  role: 'member',
  newsletter: true,
})
```

## API reference

### useFormBuilder options

| Option          | Type                                   | Description                                       |
| --------------- | -------------------------------------- | ------------------------------------------------- |
| `fields`        | `FormFieldDefinition[]`                | Ordered definition list rendered by UiFormBuilder |
| `schema`        | `StandardSchemaV1`                     | Optional form-level validation schema             |
| `initialValues` | `Partial<T>`                           | Initial state used by dirty/touched comparison    |
| `onSubmit`      | `(values: T) => void \| Promise<void>` | Called after successful validation                |

### useFormBuilder returns

| Key             | Type                              | Description                                                  |
| --------------- | --------------------------------- | ------------------------------------------------------------ |
| `fields`        | `ComputedRef<FormBuilderField[]>` | Field definitions with reactive `error` merged from Formwerk |
| `values`        | `PartialDeep<T>`                  | Reactive full form values                                    |
| `isSubmitting`  | `Ref<boolean>`                    | Submit in progress flag                                      |
| `wasSubmitted`  | `Ref<boolean>`                    | Set to true after successful submit                          |
| `isDirty`       | `(path?) => boolean`              | Dirty check for form or field path                           |
| `isTouched`     | `(path?) => boolean`              | Touched check for form or field path                         |
| `isValid`       | `(path?) => boolean`              | Validity check for form or field path                        |
| `handleSubmit`  | `(e?: Event) => Promise<void>`    | Native submit handler                                        |
| `setFieldValue` | `(name, value) => void`           | Programmatic value setter                                    |
| `reset`         | `(values?) => Promise<void>`      | Reset helper                                                 |
| `formContext`   | `FormContext`                     | Low-level Formwerk context                                   |

### UiFormBuilder props

| Prop          | Type                 | Default  | Description                            |
| ------------- | -------------------- | -------- | -------------------------------------- |
| `fields`      | `FormBuilderField[]` | required | Rendered field list                    |
| `submitting`  | `boolean`            | `false`  | Disables submit button + spinner state |
| `submitLabel` | `string`             | `Submit` | Default submit button text             |
| `cols`        | `1 \| 2 \| 3`        | `1`      | Responsive column count                |

### UiFormBuilder events

| Event    | Payload | Description                   |
| -------- | ------- | ----------------------------- |
| `submit` | `Event` | Forwarded native submit event |

## Supported field types

`UiFormField` resolves these by `type`:

- text, email, password, tel, url
- number
- search
- textarea
- select
- checkbox
- switch
- toggle
- radio
- combobox, autocomplete
- file
- otp
- tags
- date
- time
- datetime
- slider
- color
- editable
- rating

For extended fields and specialized patterns, see [docs/5.components/2.forms/5.specialized.md](docs/5.components/2.forms/5.specialized.md).

## Practical patterns

### Server-prefill after mount

```ts
onMounted(async () => {
  const user = await api.users.getCurrent()
  setFieldValue('firstName', user.firstName)
  setFieldValue('email', user.email)
  setFieldValue('role', user.role)
})
```

### Disable submit until valid and changed

```html
<UiButton type="submit" :disabled="isSubmitting || !isDirty() || !isValid()">Save</UiButton>
```

### Show values for debugging in docs/dev

```html
<pre>{{ JSON.stringify(values, null, 2) }}</pre>
```

## When to use UiForm instead

Use `UiForm` directly when:

- your layout is highly custom and not grid-based
- you use nested groups/repeaters extensively
- you need complete control over each field position

Use Form Builder when the form structure is mostly data-driven and repeatable.
