# Data Tables

Vuestrata exposes table functionality in layers:

- `createColumns()` builds typed column defs (link, status, money, date) without duplicating `header` / `meta.label` or writing `h(Table*Cell)`.
- `useDataTable()` manages TanStack state, row models, manual server-side mode, expansion, and selection.
- `useServerTable()` binds a collection query to that state — the path every list page should use.
- `UiDataTable` is the low-level semantic renderer for an existing TanStack table instance.
- `UiDataGrid` is the richer shell with built-in toolbar search, column filters, selection, pagination, column visibility, expandable rows, and flat-row virtualization.

::component-showcase{name="data-table"}
::

The live preview covers ten capability examples: a rich client grid, the low-level renderer, a server-backed query, typed cells, row selection, tree rows, virtual rows, empty and error states, and a public API directory (JSONPlaceholder, with a local fallback).

## Server-backed list (the default)

Collection list pages use `useServerTable` plus `createColumns`. Do **not** wire `useDataTable` to a query yourself — the table needs a row count, the count comes from the query, and the query needs the table's filters. Written by hand that is a temporal dead zone that type-checks and crashes on load.

```ts
import { createColumns } from '@/composables/useDataTable'
import { useServerTable } from '@/composables/useServerTable'

const col = createColumns<Customer>()
const columns = computed(() => [
  col.link('company', {
    label: t('customers_col_company'),
    width: '18rem',
    to: (row) => `/dashboard/customers/${row.id}`,
    sublabel: (row) => `${row.city}, ${row.country}`,
  }),
  col.text('contactName', { label: t('customers_col_contact'), width: '14rem' }),
  col.status('status', {
    label: t('common_status'),
    variant: customerStatusVariant,
    labelFor: (status) => t(`customers_status_${status}`),
  }),
  col.money('mrr', { label: t('customers_col_mrr') }),
  col.date('lastContactAt', { label: t('customers_col_last_contact') }),
])

const { table, isLoading, isError, refetch } = useServerTable({
  columns,
  query: useCustomersQuery,
  extra: () => ({ status: status.value, plan: plan.value }),
})
```

```vue
<template>
  <UiDataGrid
    :table="table"
    :loading="isLoading"
    :error="isError"
    :search-placeholder="t('customers_search_placeholder')"
    :empty-text="t('customers_empty')"
    @retry="refetch"
  />
</template>
```

`createColumns` helpers:

| Helper    | Cell                              | Defaults                      |
| --------- | --------------------------------- | ----------------------------- |
| `text`    | accessor value, optional `format` | —                             |
| `link`    | `TableLinkCell`                   | cell label = accessor value   |
| `status`  | `TableStatusCell`                 | width `9rem`                  |
| `money`   | `TableMoneyCell`                  | `align: 'end'`, width `9rem`  |
| `date`    | `TableDateCell`                   | `align: 'end'`, width `11rem` |
| `display` | custom `(row) => …`               | —                             |

A single `label` sets both the header and `meta.label`. Pass `filter: 'text'` (or `{ variant, options, placeholder }`) when the grid should show a column filter. Custom cells still go through `createColumnHelper`.

## Client-side grid

Use `useDataTable` when the full dataset is already in memory.

```ts
import { createColumns, useDataTable } from '@/composables/useDataTable'

const col = createColumns<User>()
const columns = [
  col.text('name', {
    label: 'Name',
    filter: { variant: 'text', placeholder: 'Filter users' },
  }),
  col.text('role', {
    label: 'Role',
    filter: {
      variant: 'select',
      options: [
        { label: 'Admin', value: 'admin' },
        { label: 'Member', value: 'member' },
      ],
    },
  }),
  col.text('active', { label: 'Active', filter: 'boolean' }),
]

const { table } = useDataTable({
  data: users,
  columns,
  enableFiltering: true,
  enablePagination: true,
  enableRowSelection: true,
  enableColumnVisibility: true,
  pageSize: 10,
})
```

```vue
<template>
  <UiDataGrid :table="table" selectable />
</template>
```

## Low-level renderer

Use `UiDataTable` when the page already owns its own toolbar, filters, or pagination chrome and only needs a table renderer.

```vue
<template>
  <UiDataTable :table="table" empty-text="No rows to display." />
</template>
```

## Column metadata

`UiDataGrid` reads its richer behavior from `columnDef.meta`. `createColumns` fills this in from `label` / `align` / `width` / `filter`.

- `meta.label` controls the human-readable label used in menus and filter UIs.
- `meta.align` supports `start`, `center`, and `end` alignment.
- `meta.filter.variant` supports `text`, `select`, and `boolean` filter controls.
- `meta.filter.options` provides option lists for `select` filters.

Column filters default **on** for client tables and **off** for `manualFiltering` (server) tables. Pass `show-column-filters` to override.

## Error, loading, empty

These are three distinct states. An error is not an empty list: showing "no rows match" for a failed request tells the user their filters are wrong when the data is simply unknown. Pass `:error` and listen for `@retry` on `UiDataGrid`.

## Expansion And Tree Rows

- Use `enableExpanding` plus `getRowCanExpand` when the grid should show expandable detail panels.
- Provide the `expanded-row` slot on `UiDataGrid` to render the detail content.
- Use `getSubRows` and a stable `getRowId` when the table should render tree rows.

## Sorting

Click column headers to toggle sorting. Multi-column sorting is supported with shift-click in the TanStack state layer.

## Pagination

`UiDataGrid` exposes built-in page navigation and page-size controls. `UiDataTable` leaves those controls to the page. Server tables take the total from `table.options.rowCount`; `:total-rows` is only an override.

## Row Selection

Enable row selection in `useDataTable()` and pass `selectable` to `UiDataGrid`.

## Column Visibility

Enable column hiding in `useDataTable()` and keep `showColumnVisibility` enabled on `UiDataGrid`.

## Virtual Rows

- Virtual mode is available through the `virtual` prop on `UiDataGrid`.
- The current contract is flat rows only.
- Expanded detail rows, tree rows, and error states intentionally fall back to the non-virtual renderer.

## Embedded

Pass `embedded` when the grid lives inside a `UiPanel` (or any other card). That drops the grid's own border, radius, and shadow so the page is not a card nested in a card. List pages that _are_ the card keep the default chrome.

## Compatibility Matrix

| Capability        | `UiDataTable` | `UiDataGrid` client mode | `UiDataGrid` manual/server mode |
| ----------------- | ------------- | ------------------------ | ------------------------------- |
| Sorting           | Via table API | Yes                      | Yes                             |
| Global search     | External UI   | Yes                      | Yes                             |
| Column filters    | External UI   | Yes                      | Off by default                  |
| Pagination        | External UI   | Yes                      | Yes                             |
| Row selection     | External UI   | Yes                      | Yes                             |
| Column visibility | External UI   | Yes                      | Yes                             |
| Expanded rows     | External UI   | Yes                      | Yes                             |
| Tree rows         | External UI   | Yes                      | Yes                             |
| Error retry       | External UI   | Yes                      | Yes                             |
| Virtual rows      | No            | Flat rows only           | Flat rows only                  |
