# Data Tables

Vuestrata uses vueye-table for table state and headless rendering. TanStack Query
still owns requests, caching, and mutations. QueryWeave gives routed lists
shareable search, filters, sorting, and pagination.

- `createColumns()` builds native typed columns with text, link, status, money, date, and custom cells.
- `useDataTable()` creates a reactive Vueye binding and disposes it with the component scope.
- `useServerTable()` connects a collection query to a manual Vueye binding.
- `UiDataTable` renders an existing binding as a semantic table.
- `UiDataGrid` adds search, filters, selection, column visibility, pagination, expansion, and flat-row virtualization.

::component-showcase{name="data-table"}
::

The preview covers ten examples: a rich client grid, the low-level renderer,
a server query, typed cells, selection, trees, virtual rows, empty and error
states, and a public API directory with a local fallback.

## Server-backed lists

Use `useServerTable` for a collection returned by `createCollectionApi`. It
creates the query before the table, keeping reactive rows and totals connected
without circular initialization.

```ts
import { createColumns } from '@/composables/useDataTable'
import { useServerTable } from '@/composables/useServerTable'

const col = createColumns<Customer>()
const columns = computed(() => [
  col.link('company', {
    label: t('customers_col_company'),
    width: 288,
    to: (row) => `/dashboard/customers/${row.id}`,
    sublabel: (row) => `${row.city}, ${row.country}`,
  }),
  col.text('contactName', { label: t('customers_col_contact'), width: 224 }),
  col.status('status', {
    label: t('common_status'),
    variant: customerStatusVariant,
    labelFor: (status) => t(`customers_status_${status}`),
  }),
  col.money('mrr', { label: t('customers_col_mrr') }),
  col.date('lastContactAt', { label: t('customers_col_last_contact') }),
])

const { table, isLoading, isError, refetch } = useServerTable({
  columns,
  query: useCustomersQuery,
  queryState: props.queryState,
  rowKey: 'id',
})
```

```vue
<template>
  <UiDataGrid
    :table="table"
    manual
    :loading="isLoading"
    :error="isError"
    :search-placeholder="t('customers_search_placeholder')"
    :empty-text="t('customers_empty')"
    @retry="refetch"
  />
</template>
```

The feature screen receives `queryState` from its route page. Define the query
model in the owning domain, using `defineListQueryModel` from
`~/lib/table-query`, then bind it in the page with `useListRouteState`. The page
passes that binding into its screen. Feature code does not read router state.

The shared list model validates supported page sizes, sortable columns, and
domain filter choices. Search waits 300 ms and replaces the current history
entry together with a reset to page 1. Pagination adds a history entry. Sort,
filter, and page-size changes reset the page in the same navigation. Back,
Forward, reload, unrelated query parameters, and URL hashes keep working.

Selections, hidden columns, expansion, and open menus stay local to the screen.
Keep collection request contracts unchanged: the helper translates native table
state into the existing `page`, `pageSize`, `search`, `sortBy`, and `sortOrder`
fields.

For an embedded example without a route, the live server demo shows a native
manual `useDataTable` binding with local filters. It creates its query first,
then passes the query's reactive items and total into the binding.

## Client-side grids

Use `useDataTable` when all rows are already in memory. Its options are the
native Vueye options, including `rowKey`, `paginate`, `selectionMode`,
`initialState`, controlled `state`, and `onStateChange`.

```ts
import { createColumns, useDataTable } from '@/composables/useDataTable'

const col = createColumns<User>()
const columns = computed(() => [
  col.text('name', {
    label: 'Name',
    filter: { variant: 'text', placeholder: 'Filter users' },
  }),
  col.text('role', {
    label: 'Role',
    filter: {
      variant: 'select',
      options: [
        { label: 'Admin', value: 'admin' },
        { label: 'Member', value: 'member' },
      ],
    },
  }),
])

const { table, state, selectedRows } = useDataTable({
  data: users,
  columns,
  rowKey: 'id',
  selectionMode: 'multiple',
  initialState: { pagination: { page: 1, pageSize: 10 } },
})

function clearSelection() {
  table.value.clearSelection()
}
```

```vue
<template>
  <UiDataGrid :table="table" selectable />
</template>
```

`table` is a shallow ref. Templates unwrap it; scripts use `table.value`.
`state` is read-only. Change state through named operations such as
`search(text)`, `sort(column, direction)`, `filter(column, value)`,
`goToPage(page)`, `setPageSize(size)`, or `setState(patch)`. Pages start at **1**.
Reactive fields are direct properties: `table.value.rows`, `.pageCount`,
`.page`, and `.rowCount`.

Pass reactive columns as a computed value, rather than `columns.value`.
Locale changes rebuild the client binding with its current state, so translated
headers, search comparisons, and formatting update together.

## Columns and rich cells

Native columns use `id`, an optional `accessor`, numeric widths in pixels, and
`sortable`. `createColumns` supplies the Vuestrata renderer metadata.

| Helper    | Purpose                                                     | Default width |
| --------- | ----------------------------------------------------------- | ------------- |
| `text`    | A value with optional plain-text `format` and rich `render` | Automatic     |
| `link`    | `TableLinkCell`, with destination and optional sublabel     | Automatic     |
| `status`  | `TableStatusCell`, with translated text and variant         | 144 px        |
| `money`   | `TableMoneyCell`, aligned to the end                        | 144 px        |
| `date`    | `TableDateCell`, aligned to the end                         | 176 px        |
| `display` | A custom cell, with optional plain-text `text(row)`         | Automatic     |

`format` returns a string. Vueye uses that text when searching, copying, and
exporting. Rich content belongs in `render` for a text column or `cell` for a
display column. Both receive `{ row, value, column, rowKey }`, where `row` is
the original application record and `rowKey` is its stable identity.

```ts
const columns = [
  col.text('name', { label: 'Name', width: 240 }),
  col.text('email', {
    label: 'Email',
    render: ({ row, value }) => h('a', { href: `mailto:${row.email}` }, String(value)),
  }),
  col.display('actions', {
    label: 'Actions',
    sortable: false,
    cell: ({ row }) => h(UiButton, { onClick: () => edit(row) }, () => 'Edit'),
  }),
]
```

Filter controls use `meta.filter.variant`: `text`, `select`, or `boolean`.
Use `filter: 'text'` or `{ variant, placeholder, options }` with a factory.
Column filters are on by default. Pass `manual` to `UiDataGrid` for a server
binding to default them off. `show-column-filters` overrides the presentation.

## Rendering and interaction

Use `UiDataTable` when the surrounding page owns its toolbar and pagination:

```vue
<UiDataTable :table="table" empty-text="No rows to display." />
```

- Sorting uses accessible header buttons. Shift-click adds another sort rule.
- Set `rowKey` for stable selection across paging, sorting, and data refreshes. Pass `selectable` to show checkboxes.
- Column visibility is local. Keep `show-column-visibility` enabled to show its menu.
- Tree rows use `getChildren` and a stable `rowKey`. Detail rows use `getRowCanExpand(row)` and the `expanded-row` slot, which receives the raw `row`, `rowKey`, and native `tableRow`.
- `virtual` renders long flat lists efficiently. Trees, detail expansion, and errors use the regular renderer.
- Pass `embedded` inside a panel to remove duplicate borders, radius, and shadow.

Loading, error, and empty are distinct states. Pass `:error` and handle `@retry`
instead of presenting a failed request as a list with no matching rows.

## Cell slots and loading

Both renderers accept an optional `cell-<columnId>` slot. It receives the raw
typed `row`, the accessor `value`, the native `column`, and a stable `rowKey`:

```vue
<UiDataGrid :table="table">
  <template #cell-name="{ row, value, rowKey }">
    <RouterLink :to="`/people/${row.id}`" :data-row-key="rowKey">{{ value }}</RouterLink>
  </template>
</UiDataGrid>
```

Slots override rich cell rendering while leaving the column's plain-text
`format` intact. Detail content uses `expanded-row` with `row`, `rowKey`, and
`tableRow`. Selection, visibility, and expansion stay local to the binding.

The public renderers load their headless implementation on demand. Pass
`loading`, `error`, and `@retry` to `UiDataGrid` for query feedback, and `manual`
for server-side operations. `UiDataTable` accepts `table`, `emptyText`, and
`ariaLabel` for a minimal semantic table. Widths are numeric pixels on columns;
use `maxBodyHeight` and `virtualRowHeight` on the grid for flat virtualization.

## CSV export

The binding's `exportRows()` returns correctly escaped CSV for the current
filtered and sorted rows across all client-side pages. It uses plain-text
column formatting, never rendered HTML. A manual server table only holds its
loaded page; use a backend export endpoint for a complete remote collection.

```ts
const csv = table.value.exportRows()
const blob = new Blob([csv], { type: 'text/csv;charset=utf-8' })
```

The table showcase downloads that result as `products.csv`.
