# Dashboard

The dashboard is a **template**, not a finished product. Everything on it is
domain-neutral (revenue, users, churn, teams) so it can be re-pointed at your
own metrics without unpicking bespoke logic.

## How it is put together

```
analytics/
├── types/dashboard.ts          # zod schemas — the API contract
├── composables/
│   ├── useDashboardQueries.ts  # one query per endpoint, schema-validated
│   └── useChartColors.ts       # ECharts colours from semantic tokens
├── components/                 # one component per panel
└── pages/index.vue             # composition only
```

`pages/index.vue` owns exactly two things: the filter state, and the grid. Every
panel fetches its own data and renders its own loading, empty and error states.
That is deliberate — a single page-level `loading` flag means one slow endpoint
blanks the whole board.

## The contract comes first

Each endpoint is described once in `types/dashboard.ts` and consumed by **both**
sides: the MSW handler builds its response with `schema.parse()`, and the query
validates with `schema.parse()` on the way in.

```ts
export const dashboardStatsSchema = z.object({
  kpis: z.array(kpiSchema),
  generatedAt: z.string(),
})
```

> **Why this matters.** The handler and the query used to declare completely
> different shapes — the handler returned `activeUsers`/`growth`/`churnRate`,
> the query read `activeProjects`/`satisfaction`/`*Trend`. Nothing failed. The
> dashboard rendered empty sparklines, `0`, `—`, and a raw unformatted `48205`,
> and looked entirely confident doing it. Schema validation on both sides turns
> that into a loud error.

### Money is never a formatted string

```ts
{ amount: 4523100, currency: 'USD' }   // ✅ minor units + ISO-4217
"$45,231"                              // ❌
```

A formatted string cannot be summed, compared, or localized, and it hardcodes
English grouping and a leading `$` for every locale. Formatting is the view's
job, via `useFormatters()`.

### Trends carry meaning, not just a sign

```ts
{ changePercent: -17.8, direction: 'down', isImprovement: true, … }
```

`isImprovement` is separate from `direction` because **down is not always bad** —
falling churn is good news. Tying colour to the arrow would be wrong half the
time, and `UiTrendDelta` reads this to decide whether green or red is correct.

`comparedTo` is a range key (`7d` / `30d` / `90d`), not display copy. English
`"previous 7 days"` cannot be translated — the same trap as a pre-formatted
`"$45,231"`. Closed label sets on the board (`dash_compared_*`, `dash_kpi_*`,
`dash_range_*`, `dash_source_*`, `dash_funnel_stage_*`, `dash_action_*`) are
looked up with **string literals**. A constructed key (`t('dash_compared_' +
range)`) is dropped by `@intlify/unplugin-vue-i18n` and ships as the key on
the board.

## Adding a panel

1. **Add a schema** to `types/dashboard.ts`.
2. **Add a handler** in `app/mocks/handlers/dashboard.ts`, building the response
   through that schema. Keep the data deterministic — seeded, not
   `Math.random()` — so the demo is stable and e2e can assert on it.
3. **Add a query** in `useDashboardQueries.ts`:
   ```ts
   export function useMyPanelQuery(filters: Ref<DashboardFilters>) {
     return createDashboardQuery('my-resource', myPanelSchema, filters)
   }
   ```
4. **Build the component** on `UiPanel`, which handles the loading/empty/error
   triad for you:
   ```vue
   <UiPanel :title="…" :loading="loading" :error="error" :empty="isEmpty" @retry="…">
     <!-- content -->
   </UiPanel>
   ```
5. **Place it** in the 12-column grid in `pages/index.vue`.

## Filters

`DashboardFilters` (`range` + `segment`) is part of **every** query key, so
changing either refetches the whole board. Panels never end up showing figures
from different windows side by side under the same heading.

The mock backend scales its figures by segment, so the filter visibly does
something — a filter that returns identical data teaches the reader it is
decorative.

On a phone the filter bar **stacks**: range chips full-width, then the
segment select. A wrapping row that is sized by its content never wraps —
the box grows, and the 390px board used to scroll sideways by ~57px.

## Charts

Charts render to a `<canvas>`: one opaque node with no internal structure, and
no text to select or search. `BaseChart` compensates, but only if you supply the
information:

```vue
<BaseChart
  :option="option"
  :summary="summary"          <!-- describes the TREND, not the title -->
  :data-columns="columns"     <!-- headers for the fallback table -->
  :data-rows="rows"           <!-- the numbers, in a visually-hidden <table> -->
/>
```

- **`summary`** should say what a sighted reader takes from the shape. "Revenue
  rose 12% over seven days, ending at $48.5K" is useful; "Revenue chart" repeats
  the heading and adds nothing.
- **`dataRows`** is not optional in spirit. Without it the numbers do not exist
  for anyone not looking at the canvas.
- Series colours come from `--color-chart-1…8` via `useChartColors()`. They
  alternate hue family and lightness so adjacent series stay distinguishable in
  greyscale and with a colour-vision deficiency.
- Never let colour be the only difference between two series — add a dash
  pattern, a direct label, or rely on the table.
- **Money on a chart is major units.** Activity `revenue` is cents. Plot
  `toMajorUnits(revenue)` on its own Y-axis; never share that axis with a
  count series. A single axis of cents vs users flattens the user line and
  labels money as a compact count of cents. The fallback table still formats
  through `currency()`, which takes minor units.
- **Reduced motion.** ECharts animates on the canvas, so `motion.css` cannot
  reach it. `BaseChart` sets `animation: false` when
  `prefers-reduced-motion: reduce` is on. Do not pass a raw `<VChart>` — the
  wrapper is what honours the preference.

The conversion funnel is deliberately **not** an ECharts funnel: it is a
semantic `<ol>` with proportional bars, so every stage carries its own label,
count and drop-off as real text.

The revenue donut has **one** legend: the share list under the chart. An
ECharts legend on the same canvas would repeat names and colours without the
numbers that make the split readable. Segment names are `dash_source_*` keys,
looked up with string literals the same way as `dash_compared_*`.

## Formatting

`useFormatters()` wraps `Intl` and caches the formatters per locale:

| Function                               | Use                             |
| -------------------------------------- | ------------------------------- |
| `currency(minorUnits, code, compact?)` | Money. Input is cents.          |
| `number(value, compact?)`              | Counts.                         |
| `percent(value)`                       | `12.5` → `12.5%`.               |
| `signedPercent(value)`                 | Deltas — always shows the sign. |
| `date` / `dateTime`                    | Locale date formats.            |
| `relativeTime`                         | "3 hours ago", localized.       |

Never build these by hand. `${n}h ago` is English-only and gets pluralization
wrong in most other languages.

## Re-pointing it at your domain

The fastest path from this template to your product:

1. Rename the KPIs in `kpiSchema` (`revenue`, `activeUsers`, … → yours) and
   update the `dash_kpi_*` translation keys.
2. Replace the handlers with real endpoints; keep the schemas as the contract
   you agree with your backend.
3. Delete panels you do not need — each is a self-contained file.
4. Keep `UiPanel`, `UiStatCard`, `UiTrendDelta`, `UiEmptyState` and
   `useFormatters`; they carry the accessibility and localization behaviour and
   are not domain-specific.
