# Ui Wrapper Architecture

Vuestrata keeps a single public component layer under `src/modules/app/components/ui/`. App code imports `Ui*` wrappers, and those wrappers compose shared logic from `src/modules/app/components/ui/base/` where needed.

## Structure

```
src/modules/app/components/ui/
├── UiButton.vue
├── UiDialog.vue
├── UiTextField.vue
└── base/
	├── BaseButton.vue
	├── BaseDialogField.vue
	├── BaseTextFieldInput.vue
	└── ...
```

## Responsibilities

- `Ui*` wrappers: stable public imports for pages, layouts, and feature modules.
- `base/*`: shared Formwerk bindings, render helpers, labels, hints, error output, and repeated interaction logic.
- `core/lib/*`: framework-agnostic utilities used beneath the component layer.

## Why Keep The Split

The wrapper/base split lets the repo keep one import contract without duplicating shared field logic across dozens of components. When a field needs extra behavior such as labels, validation messages, or keyboard handling, the base component owns it and the `Ui*` wrapper stays thin.

## Adding A New Ui Component

1. Add the public wrapper in `src/modules/app/components/ui/Ui<Name>.vue`.
2. If the component shares logic with existing fields, extract or reuse a helper in `src/modules/app/components/ui/base/`.
3. Keep the wrapper API aligned with the rest of the `Ui*` surface.
4. Add or update the relevant component tests under `test/component/ui/`.
